# BrightnessControl

Утилита для Windows 11, управляющая яркостью нескольких мониторов сразу —
живёт в системном трее, без окон на переднем плане, пока не понадобится.

## Возможности

- **Единое управление яркостью** — по отдельному монитору или все сразу.
  Источники: DDC/CI (внешние мониторы), WMI (встроенная панель ноутбука),
  программный оверлей как fallback для мониторов без поддержки DDC/CI.
- **Быстрый доступ из трея** — скролл колеса мыши над иконкой меняет
  яркость на лету, левый клик открывает лёгкий поповер со слайдерами,
  правый — полные настройки.
- **Автоматизация** — правила по времени суток, по активному
  приложению/окну, и адаптивное приглушение по бездействию; можно
  сочетать несколько условий в одном правиле.
- **"Замочек" на монитор** — фиксирует яркость конкретного монитора,
  автоматизация и общий слайдер "все сразу" его не трогают.
- **Гибкое хранение настроек** — Portable (конфигурация рядом с exe)
  или обычная установка (копия в выбранную папку, ярлык в Пуск,
  автозапуск) — выбирается при первом запуске.
- **Автообновление** — фоновая проверка новых версий на GitHub,
  скачивание и установка одним подтверждением, без стороннего
  установщика.
- **Своя иконка трея** — форма, цвет и масштаб настраиваются; можно
  импортировать собственные изображения. Акцентный цвет подхватывается
  из системной темы Windows или задаётся вручную.

## Требования

- Windows 10 версии 2004 (сборка 19041, "May 2020 Update") или новее,
  включая Windows 11.
- Для внешних мониторов — поддержка DDC/CI (у подавляющего большинства
  современных мониторов она есть и включена по умолчанию).
- Отдельно устанавливать .NET не нужно — приложение self-contained.

## Установка

Готовые сборки — на странице

установиться (то же плюс ярлык в Пуск и на Рабочем столе, автозапуск).

## Использование

После запуска приложение сворачивается в системный трей:

- **Скролл колёсиком** над иконкой — меняет общую яркость.
- **Левый клик** — лёгкий поповер с быстрыми слайдерами.
- **Правый клик** — полное окно настроек (мониторы, автоматизация,
  оформление, обновления).

## Сборка из исходников

```
dotnet build
dotnet run --project src/BrightnessControl.App/BrightnessControl.App.csproj
```

Публикация самодостаточного однофайлового exe (со всеми зависимостями
внутри):

```
dotnet publish src/BrightnessControl.App/BrightnessControl.App.csproj -p:PublishProfile=win-x64
```

## Версионирование

Пошаговый чек-лист выпуска релиза (что именно бампить, как собирать,
что делать с тестовыми релизами) — [RELEASING.md](RELEASING.md). Здесь
— только объяснение самой схемы.

Версия состоит из четырёх чисел `Major.Minor.Build.Revision`
(например `0.1.2.0`), и каждое число значит нечто конкретное — это не
обычный [SemVer](https://semver.org/), а осознанно расширенная схема под
процесс разработки этого конкретного проекта.

| Число | Название | Что означает |
|---|---|---|
| 1-е (Major) | **Релизы** | Крупная версия, предназначенная для ВСЕХ пользователей. Публикуется как обычный (не pre-release) релиз на GitHub. |
| 2-е (Minor) | **Обновления** | Собранный за время разработки набор готовой, связанной между собой работы (новые функции + накопленные исправления) — тоже публикуется как обычный релиз, просто не настолько крупный, чтобы называться отдельным Релизом. |
| 3-е (Build) | **Фиксы** | Активная разработка. Тем же каналом самообновления автор программы перепрошивает свою рабочую копию во время работы над проектом — вместо ручного копирования файла. Может как попасть в публичный релиз, так и остаться промежуточным шагом. |
| 4-е (Revision) | **Дебаг-тесты** | Используется ИСКЛЮЧИТЕЛЬНО для проверки самого механизма обновления (скачивание, замена файла, перезапуск). Такие версии всегда публикуются с пометкой GitHub "pre-release" и удаляются сразу после проверки — обычный пользователь их никогда не увидит. |

### Как это сочетается с каналом обновлений

Число версии говорит **что это за изменение**, а флаг "pre-release" на
GitHub — **видно ли это обычным пользователям вообще**. Это две разные,
независимые друг от друга вещи:

- Переключатель **"Включать бета-версии"** в настройках приложения
  решает, учитываются ли вообще релизы с пометкой pre-release
  (то есть Дебаг-тесты) при поиске обновлений.
- Переключатель **"Канал обновлений"** решает, НАСКОЛЬКО мелкие
  изменения стоит предлагать среди обычных (не pre-release) релизов:
  - **Только релизы** — только когда выросло 1-е число (Major).
  - **Релизы + обновления** — 1-е ИЛИ 2-е число (Major.Minor), 3-е и 4-е
    игнорируются полностью.
  - **Все версии** — сравнивается вся версия целиком, включая Фиксы.

Дебаг-тестовые версии не предлагаются НИ ОДНИМ из уровней канала, пока
не включена галочка "Включать бета-версии" — независимо от выбранного
канала.
